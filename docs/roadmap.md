- **~~内置工具服务拆分~~ ✅ 已完成（2026-10-25，P0/P1/P2）**：把 tool registry 从 orchestrator 拆成独立 `tool-service`（:8008，catalog/执行/审计，沙箱经 workspace-service），装配开关 `TOOL_SERVICE_ENABLED`。P0 只读工具（`read/glob/grep/list_dir`）、P1 受控写（`write/edit` + 读前置 + per-run 配额 + 审计富字段）、P2 `ask_question` 全栈（`awaiting_input` + `ask_gate` + answer API + 前端提问卡片）与 `search_knowledge` 代理已落地，旧 `code_*` 工具与 alias 已下线；设计与验收见 [design/tool-service.md](./design/tool-service.md)。
- **~~M0-02 七服务容器化~~ ✅ 已完成**：`deploy/docker/python-service.Dockerfile`（7 个 Python 服务复用，`SERVICE` 选入口）+ `deploy/docker/web.Dockerfile` + `deploy/docker-compose.yml` 全量编排（pg/redis/migrate/7 服务/web，:8080）；CI 增 `docker-build` job（= 重构 R-36 关闭）。
- **M0-03 云 PG/云 Redis 接入**：生产 URL 注入即用；开发保持 SQLite/本地 Redis；CI 对云 PG 跑迁移与集成测试；限流已于 2026-11-10 切到 Redis（P0-5：配 `REDIS_URL` 走固定窗口，未配回退进程内，见 [design/rate-limiting.md](./design/rate-limiting.md)）；剩余仅云实例 URL 注入与 CI 集成。
- **~~CI 上线后~~ ✅ 已完成**：覆盖率阈值（R-31）、零网络硬门禁（R-32）、文档链接检查（`scripts/check-docs.sh`，CI `docs-check` job）。
- **~~P0-1 成本归因~~ ✅ 已完成（2026-11-09）**：网关按 litellm 本地价目表（含缓存价）算 `cost_usd` → 编排器透传 → `usage_events` 落库（新迁移）→ `/usage/summary` 出金额 → 用量页展示，并区分 platform/BYOK、单独统计未计价调用；契约见 [design/cost-attribution.md](./design/cost-attribution.md)。残余 step/phase 拆分与 BYOK 审计随后续批次。
- **~~P0-3 用量可靠投递~~ ✅ 已完成（2026-11-09）**：`UsageReporter` 先写编排器 outbox（`usage.report.v1`，独立短事务）→ dispatcher 至少一次投递 → account 按 `(account_id, event_id)` 幂等落库（迁移 `a9d4f2c8b6e1`）；入队失败回退直连、未装配 `session_factory` 行为不变，开关 `USAGE_OUTBOX_ENABLED`；契约见 [design/usage-delivery.md](./design/usage-delivery.md)。多副本 claim 锁/租约已于 2026-11-10 补齐（P0-4）；跨实例投递仍是每实例 dispatcher + 进程内总线（消费幂等兜底）。
- **~~P0-2 对话配额闸~~ ✅ 已完成（2026-11-09）**：对话直答（不建 run）现在同样受月度配额约束——`run_quota.enforce_monthly_quota` 在非流式与流式两个入口、调模型之前拦截（流的必须开流前，SSE 一旦 200 不能改状态码），非流式路径包 `UsageCollector` 并在事务提交后经 post-commit 上报 `run_id=None`；account 新增会话鉴权的 `GET /v1/usage/quota/me`，Web 用量页有配额进度条、composer 在 429 `quota.*` 时就地提示。残余：失败请求不补记、对话不占并发名额、无预算阈值通知，见 [gap-2026-11/00-refresh-2026-11-09.md](./gap-2026-11/00-refresh-2026-11-09.md) §4.2。
- **~~P0-6 MCP 出站 SSRF~~ ✅ 已完成（2026-11-09）**：出站地址收口到 `services/net_guard.py`（私网/元数据/回环/链路本地/保留/组播/CGNAT 全拒，IPv4 映射归一），`MCPClient` 首次发包前校验（覆盖 initialize/list/call 与 `/test`），`MCP_ALLOWED_HOSTS` 精确放行自建内网；注册期对字面 IP/localhost 名快速拒绝；工具面加载失败改为 warning 留痕；契约见 [design/mcp-security.md](./design/mcp-security.md)。残余 DNS rebinding TOCTOU 窗口与出站拦截指标。
- **~~P0-4 多实例三处锁~~ ✅ 已完成（2026-11-10）**：outbox `claim` 在 PG 下 `FOR UPDATE SKIP LOCKED` + 租约（命中行 `available_at=now+lease`）；worker 心跳 `renew_lease`、收尾 `mark_succeeded/finish_failure` 均校验 `status=running + locked_by`；sandbox reaper 改 `claim_expired` 原子领取 + 三段式回写。残余：SQLite 极端多进程仍可能重复 destroy（PG 无此问题）。
- **~~P0-5 限流 Redis 化~~ ✅ 已完成（2026-11-10）**：`common.security.build_rate_limiter` 按 `REDIS_URL` 选 Redis 固定窗口（`INCR`+`EXPIRE` 原子计数、跨副本共享、故障 fail-open），未配则保持进程内滑动窗口；api-gateway 与 account 动态注册限流已接，compose 默认注入；契约见 [design/rate-limiting.md](./design/rate-limiting.md)。残余固定窗口 2× 边界、无集群/指标/路由级配额。
- **~~P0-7 管理面 RBAC/审计~~ ✅ 已完成（2026-11-10）**：`users.role`（user/admin，不进 JWT，每请求读库）+ `ADMIN_EMAILS` 引导名单（只升不降，兜底放行）+ append-only `audit_logs`（写动作与业务同事务、`admin.access.denied` 独立短事务、request_id/ip/user_agent）；account-service 新增 `/v1/admin/accounts`（列表/详情/配额/角色/状态）与 `/v1/admin/audit-logs`，停用同事务吊销 refresh token 与 sessions；Web 新增 `/admin` 管理台（仅 `me.role==='admin'` 显示入口，账号/审计两页签）；契约见 [design/admin-plane.md](./design/admin-plane.md)。残余：admin 无细粒度 scope、access token 停用窗最长 1h、审计可被 DBA 改、读操作不审计。
- **agent 服务能力补齐（待决策）**：2026-11-09 复核出的 P0/P1 差距与建议排期见 [gap-2026-11/00-refresh-2026-11-09.md](./gap-2026-11/00-refresh-2026-11-09.md) §4/§7（上一版见 gap-2026-10/06）；其中 P0 项（多实例正确性、对话配额闸、MCP SSRF、管理面）决策后并入本表；P0-1 成本归因、P0-2 对话配额闸、P0-3 用量可靠投递、P0-6 MCP 出站 SSRF 已于 2026-11-09 落地，不再待决；多实例正确性（P0-4）与限流 Redis 化（P0-5）已于 2026-11-10 落地，不再待决；管理面 RBAC/审计（P0-7）已于 2026-11-10 落地，P0 七项全部关闭。工具策略引擎（P1-A）已于 2026-11-10 落地（参数级规则 + once/session/always 授权），应用级 hooks（P1-B，五事件 webhook）已于 2026-11-10 落地，恢复语义（P1-C：run 超时/优先级 + checkpoint 列表 + rewind/fork，契约见 [design/recovery.md](./design/recovery.md)）也已于 2026-11-10 落地；MCP 协议双栈（P1-H：`2025-03-26` 有状态 / `2026-07-28` 无状态分流 + `server/discover` + 客户端 auto 协商，契约见 [design/mcp-dual-stack.md](./design/mcp-dual-stack.md)）已于 2026-11-10 落地，四块机制骨架（A/B/C/H）全部收口；能力层已补两块：P1-L/M3 `web_search` 与 P1-L/M2 后台作业 `job_*` 均于 2026-11-10 落地，剩余是跨实例持久 shell（M2 后半）、eval / 成本看板与接入形态（CLI/SDK），见 gap-2026-11 §5/§7。
