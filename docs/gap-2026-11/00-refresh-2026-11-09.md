## 0. 一页结论

1. **主循环已经齐了，缺的是四块地基。** 单 run 闭环（工具 → 审批 → 执行 → 事件 → SSE → UI）、上下文压缩/记忆、技能渐进加载、子代理、模型选择/fallback、沙箱执行（exec/run_code）、Langfuse 观测栈都已落地；剩下的不是「再加一个功能」，而是钱与安全、机制层、工具面长尾、接入形态。
2. **P0 七项已全部落地（P0-1/2/3/6 于 2026-11-09，P0-4/5/7 于 2026-11-10）。** P0-1 把成本从 Langfuse span 搬到 `usage_events`（网关算价 → 编排器透传 → `/usage/summary` 聚合 → 用量页出金额，区分 BYOK/platform、单独统计未计价）；P0-3 把上报改成 outbox 至少一次 + `event_id` 幂等（见 [design/usage-delivery.md](../design/usage-delivery.md)）；P0-2 让对话直答也过月度配额闸并在非流式路径补记用量（失败请求不补记）；P0-6 把 MCP 出站地址收口到 `services/net_guard.py`（私网/元数据/回环/链路本地/保留/组播/CGNAT 全拒，`MCP_ALLOWED_HOSTS` 精确放行）并让工具面加载失败不再静默（见 [design/mcp-security.md](../design/mcp-security.md)）；P0-4 把 outbox claim / job lease / sandbox reaper 三处补成有锁有租约；P0-5 接 `REDIS_URL`，限流可跨副本共享（见 [design/rate-limiting.md](../design/rate-limiting.md)）；P0-7 落管理面 RBAC/审计：`users.role`（不进 JWT，每请求读库）+ `ADMIN_EMAILS` 引导 + append-only `audit_logs`（写动作同事务、denied 独立短线）与 Web `/admin` 管理台（见 [design/admin-plane.md](../design/admin-plane.md)）。
3. **P1 的「机制代差」四项全缺**：工具 policy 引擎、hooks、恢复语义（checkpoint/rewind/fork + run 超时/优先级）、MCP 2026-07-28 对齐。这四项是 2026-10 主流 harness 已经抬高的门槛，不是可选项。
4. **工具面只差长尾**：`web_search`、后台任务 `job_start/job_output/job_kill`、跨实例持久 shell 全仓仍为零；eval harness 与平台成本看板也缺（观测三角只差质量门禁）。
5. **前端/桌面端不缺页面，缺原地闭环**：计划编辑仍断在 `/runs`、失败无重试/消息编辑重发、无复制/重生成、无错误边界、用量页没有钱、桌面端 md/diff/审批与 `shell.run` 无 UI。
6. **排期建议**：批次 1（钱与安全，1–2 周）→ 批次 2（机制层，2–4 周）→ 批次 3（工具面/体验/接入）→ P2 生态在「有外部用户」之后再启动。

### 4.2 逐项现状与做法

- **P0-1 成本归因 ✅**：已按「网关单源计价 → 编排器透传 → `usage_events` 落库 → `/usage/summary` 聚合 → 用量页出金额」落地，详见 [design/cost-attribution.md](../design/cost-attribution.md)。要点：价目表复用 litellm 本地表（含缓存价）不新造 `pricing.py`；`usage_events` 加 `cost_usd`（NULL=未计价）与 `billing_source`（platform/byok）；未计价调用单独计数而不是按 0 元吞掉。**残余**：`step_id/phase` 维度拆分、BYOK 调用审计、金额随 usage 的可靠投递（属 P0-3）。
- **P0-2 对话配额闸 ✅**：对话直答此前只在流式路径上报 `run_id=None`，非流式 `chat.answer` 不记，且 chat 完全绕过 run 准入的双重判定。现已落地：`run_quota.enforce_monthly_quota(account_id)` 抽成公开月度闸（月度 token 用尽抛 429 `quota.monthly_tokens_exceeded`；快照取不到时仍 fail-open），非流式与流式两个入口都在**调模型之前**执行（流式必须在 `StreamingResponse` 之前，SSE 一旦 200 就不能改状态码）；对话不占 `max_concurrent_runs`（那是 run 的维度）。非流式 chat 现在包 `UsageCollector` 边界，答案落库后经 `post_commit.register_after_commit` 在提交后上报 `run_id=None`（不在请求事务里直接 report：outbox 会另开写连接与未提交事务抢 SQLite 单写锁）；没有 post-commit runtime 的直调退回同步上报。account 新增会话鉴权的 `GET /v1/usage/quota/me`，Web 用量页有本月配额进度条与剩余量，composer 在收到 429 `quota.*` 时就地提示。**残余**：失败请求已经烧掉的 token 不补记（与提交语义一致）；对话只判月度、不占并发名额；配额只能由服务端维护 `users.quota`，无自助改与预算阈值通知。
- **P0-3 用量可靠投递 ✅**：`UsageReporter.report` 现在先把 `usage.report.v1` 写进编排器自己的 outbox（独立短事务，与 run 事务解耦），dispatcher 经进程内总线投给 `UsageDeliveryConsumer`，逐条 POST 带 `event_id="<outbox id>:<样本序号>"`；account 按 `(account_id, event_id)` 唯一约束幂等，重投返回同一条。入队失败退回旧的逐条直连（best effort），未装配 `session_factory` 的部署行为不变；开关 `usage_outbox_enabled`。详见 [design/usage-delivery.md](../design/usage-delivery.md)。**残余**：outbox claim 无 `SKIP LOCKED`/租约、总线仍是进程内，多副本要等 P0-4；account 侧 failed 投递缺告警。
- **P0-4 多实例 ✅**：job claim 早已 `SKIP LOCKED`，本次补齐三处：outbox `claim` 在 PG 下 `FOR UPDATE SKIP LOCKED` 且命中行 `available_at=now+lease`（租约到期可重领）；worker 心跳每 `min(lease/3,30)` 秒 `renew_lease`，续租与收尾都校验 `status=running + locked_by=worker_id`，丢锁即停止续租并跳过 finalize；sandbox reaper 改为 `claim_expired` 原子领取（同事务把 `expires_at` 推后 300s）→ 事务外 destroy → 短事务回写，失败只在仍持租时推后 `retry_delay`。**残余**：SQLite 下极端多进程仍可能重复 destroy（PG 无此问题）；跨实例事件投递仍是每实例 dispatcher + 进程内总线（依赖消费幂等）。
- **P0-5 限流 Redis 化 ✅**：`common.security.build_rate_limiter` 按 `REDIS_URL` 选后端——未配 → 原进程内滑动窗口（行为不变）；配了 → Redis 固定窗口（`INCR`+`EXPIRE` 事务 pipeline，键 `namespace:bucket:key`，TTL=2×窗口），多副本共享计数；Redis 故障 fail-open + 结构化 warning（可用性优先）。api-gateway（/api 120/min）与 account（OAuth 动态注册 10/h）已接，compose 默认注入 `*__REDIS_URL`。**残余**：固定窗口边界最多 2× 瞬时；无集群/Sentinel（单点故障即降级为不限流）、无命中/拒绝指标、无路由级或套餐差异化配额；未配 REDIS_URL 的多副本仍各记一份。
- **P0-6 MCP 出站 SSRF ✅**：此前注册只校验 `http(s)://` 前缀，服务端直连用户填的 URL；同仓 `fetch/file_capture` 有私网防护而 MCP 没有；自动加载失败还静默吞异常。现已落地（详见 [design/mcp-security.md](../design/mcp-security.md)）：`services/net_guard.py` 作为出站校验单一真源（私网/回环/链路本地/保留/组播/未指定/CGNAT、IPv4 映射归一；`socket.getaddrinfo` 走 `asyncio.to_thread`），`MCPClient._post` 在首次发包前 memo 校验一次（覆盖 initialize/list/call 与 `/test`），命中抛 `BlockedTargetError`；`MCP_ALLOWED_HOSTS`（host 精确匹配）给自建内网开口子；`schemas/mcp.py` 注册期对字面 IP/localhost 名零网络快速拒绝；`file_capture` 改为共用同一判定函数（下载路径解析失败仍拒绝，MCP 路径放行让连接自己报错）。工具面降级不再静默：`graph/nodes/toolkit.py` 的 `_load_toolkit` 失败留 `logger.warning`（带 account_id 与错误），手动 `/test` 照旧落 `last_status/last_error`。**残余**：校验与真正连接是两次 DNS 解析，仍有 rebinding TOCTOU 窗口（未做 connect 到已校验 IP）；注册期不做 DNS 预校验；出站拦截只有日志没有指标；多副本各自读配置。
- **P0-7 管理面 RBAC/审计 ✅**：此前只剩 `/me` 与 sessions，User 无 `role`，全仓无 `/admin`、无 audit 表。现按 [design/admin-plane.md](../design/admin-plane.md) 落地：
  - **唯一角色源在库里**：`users.role`（`user`/`admin`，迁移 `f2c7b9d4a1e6`，存量回填 `user`）；角色**不进 JWT**，`require_admin` 每请求读库（`api/deps.py`），提权/降权/停用立即生效；`ADMIN_EMAILS` 只做引导（注册/登录持久化 admin、鉴权兜底放行，只升不降）。
  - **管理 API**：`/v1/admin/accounts`（q/status 过滤 + 分页 + 本月用量聚合，单条 group by 避免 N+1）、`/v1/admin/accounts/{id}`、PATCH `quota`（省略保持/`null` 清除/至少一键）、PATCH `role`（改自己 409 `admin.self_role`）、PATCH `status`（停用自己 409 `admin.self_disable`，停用同事务吊销全部 refresh token 与 sessions）、`/v1/admin/audit-logs`。
  - **审计**：`audit_logs` append-only（仓储只 add/list/count）；三个写动作与业务**同事务**落 before/after；无权限访问先落 `admin.access.denied` 独立短事务再 403（失败只 warning，不改变结论）；带 `request_id`/`ip`/`user_agent`，读端点不审计。
  - **前端**：`/admin` 管理台（账号/审计两页签、配额弹窗、角色/状态确认），入口只按 `me.role` 为 `admin` 显示（桌面/移动/命令面板统一过滤），401/403/错误态不白屏。
    **残余**：admin 无细粒度 scope（P1-A 后再考虑）；停用后旧 access token 最长 1h 仍可访问普通端点；审计无链式签名/防篡改（DBA 可改）；读操作不审计；`X-Forwarded-For` 仅在可信代理后可信。
