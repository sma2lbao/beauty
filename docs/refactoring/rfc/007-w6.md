## 1. 问题与证据（2026-10-29 实测，立项 commit 4717b3f）

### 1.1 components/console 混装外壳与业务域（R-46）

- `apps/web/src/components/console` 立项时 **41 个文件 / 9,534 行**，同时容纳三类东西：控制台外壳（console-layout / sidebar / topbar / status-bar）、通用原语（ui / dialog / markdown / diff-view / button-class）、以及各业务域组件（runs 六个、sandbox 三个、settings 三个、notifications 两个、workspace 两个、chat 两个、artifacts 一个）。
- `features/` 立项时只有 5 个域（chat / mcp / settings / sidebar / workspace），与 components/console 里的域不对应：同一域的实现被拆在两个顶层目录，读代码必须先猜位置。
- 壳层组件反向依赖业务组件：console-layout → notification-center / toast-viewport；sidebar → workspace-switcher；runs 详情直接放在 components/console 下被 pages/runs.tsx 引用。

### 1.2 超大文件（R-47 ~ R-51）

### 1.3 页面数据层两套写法（R-49 ~ R-52）

- 立项时 9 个页面直接内联 `useQuery` / `useMutation`：outbox、knowledge、login、oauth-authorize、usage、skills、runs、changes、memory；只有 chat / mcp / settings / workspace 走 `features/<domain>/use-<domain>-model.ts`。
- 页面里混着查询、变更、表单状态、轮询与视图结构，单页最大 633 行；同一域的行为逻辑无法被测试直接复用，只能从页面入口整体断言。

### 1.4 重复实现（R-48）

`formatBytes` 三份：正版 `apps/web/src/lib/presentation/format.ts:164`；副本 `apps/web/src/components/console/sandbox-file-tree.tsx:372` 与 `apps/web/src/components/console/sandbox-file-viewer.tsx:50`（二者各自实现 1024 进制与小数位截断，与正版细节略有差异）。另有 `formatSize`（format.ts:177）、`relativeTime`（format.ts:104）、`runStatusTone`（lib/presentation/run.ts:66）已集中，可直接复用。

### 1.5 结构与体量规则缺位（R-53）

- `tools/eslint-config/configs/base.js` 的 `max-lines` 仍是 W1 的临时值 **1400**（注释写明「W2 起按 playbook §7.1 收紧到 400」，未执行），对 >400 行文件零告警。
- `webLayerBoundary` 只有 3 条（lib 不得 import pages/components、components 不得 import pages、stores 不得 import pages），**没有 features 不得 import pages**，也没有「console 原语不得 import features」——本轮搬家后新边界没有防回流。
- 规则是 warn 级，需配套探针验证（命中/不命中两种样本）才能证明规则真的生效。

### 1.6 基线门禁全绿，重构有兜底

- `npx nx lint @beauty/web` EXIT 0（5.9s）；`npx nx typecheck @beauty/web` EXIT 0（4.9s）；`npx nx test @beauty/web -- --run` EXIT 0（69 files / 493 tests，11.27s）。
- 因此本轮定位为**行为等价的结构重构**：不改 UI/文案/data-testid/API 契约，靠 493 例测试与类型检查兜底。

## 2. 目标与非目标

目标（W6 出口）：

1. 域组件归位：`features/<domain>/` 承载全部业务域组件，`components/console` 只留外壳与通用原语，外壳可依赖 features、原语不可。
2. 体量收口：`apps/web/src` 非测试源文件全部 **≤400 行**（测试文件 ≤500 行）。
3. 页面只做组装：页面文件不再出现 `useQuery` / `useMutation` / 表单与轮询逻辑，数据层统一 `features/<domain>/use-<domain>-model.ts`。
4. 消除重复实现：`formatBytes` 只保留 `lib/presentation/format.ts` 一处。
5. 规则防回流：`max-lines` 收紧到 500（源文件再以 400 为软目标）并补 features/console 边界规则，探针验证命中。
6. 文档收口：RFC-007、verification/007、baseline W6 段、roadmap W6 段与遗留项、AGENTS.md 的 apps/web 结构描述同步。

非目标：

- 不改功能、交互、中文文案、`data-testid`、导出名、路由与既有 import 路径（页面入口保持 `pages/<x>.tsx` 的 `<X>Page` 具名导出）。
- 不新增依赖、不换状态管理/数据请求方案、不做视觉改版、不动 `packages/design` 与 `packages/console-ui`。
- 不把 `lib/*-api.ts` 拆到子目录（避免 51 处 import 全改），只做 `lib/runs-api.ts` 的内部拆分且对外导出不变。
- 不动 `apps/desktop` / `apps/site` / Python 服务。

## 4. 依赖与顺序

1. R-46 先落地并全绿（纯机械搬家，是后续并行的前提）。
2. R-47 ~ R-52 可并行：写 scope 互不重叠（features/{runs,sandbox,memory,skills,workspace,chat,knowledge,outbox,changes,usage,auth} 与 pages/ 的对应文件），任务板登记 owner 与 write scope；teammate 禁止 `git commit/stash/reset/checkout`，改完只回报。
3. R-53 / R-54 在全部拆分收口后由 lead 串行做：先全量门禁与体量复核，再收紧规则并探针验证，最后写文档并分项提交。

共享工作树纪律（playbook §10.4）：每个 R 项独立提交、可单独 revert；并发期间以 typecheck + 493 例测试为快速回归，最终门禁在所有人收口后统一复跑。

## 5. 风险与回滚

| 风险                  | 控制                                                                     | 回滚                        |
