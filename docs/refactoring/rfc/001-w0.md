## 1. 问题与证据
- 无 CI（无 .github），合并门禁全靠人工（playbook §9.4）。
- 受限环境 Python target 直接失败：uv 缓存不可写 → EXIT 1（playbook §9.7 实测）。
- Nx 图中 Python 项目无边：workspace 依赖未映射成 implicitDependencies（playbook §9.2），nx affected 与 test.dependsOn [^build] 失效。
- 文档三处权威互斥（architecture.md v1 过时 vs architecture-v2.md vs tasks-m0 依据 v2，见 ops 审计 §2）。
- 根 package.json 缺 test/format/gate 脚本、无 engines/.nvmrc。

## 2. 目标与非目标
- 目标：让后续每个改动可被验证（门禁脚本+CI 骨架）、可被记录（单一真源+归档）、依赖关系可见（Nx 图）。
- 行为等价定义：七个服务端口/健康检查、API/SSE/outbox 语义、测试零网络全部不变；本 RFC 不改任何业务代码。
- 非目标：不做覆盖率阈值（W3 R-31）、不修 dev.sh 缺陷（R-15）、不动 architecture 之外的服务文档、不引入 commitlint 工具链（仅约定+模板）。

## 3. 方案
- R-01 优先方案：给每个 Python project.json 的 run-commands 类 target 增加 env 默认值（UV_CACHE_DIR/UV_PYTHON_INSTALL_DIR 指向仓库本地，仅当外部未设置时——脚本内做 ${VAR:-默认}）；ruff 类 executor 若 schema 不支持 env 则降级为文档化（gate/CI/dev.sh 三处显式导出）并在 roadmap 记遗留。
- R-04：服务 implicitDependencies=[common,database(/events)]，库不加反向边；验证 nx graph。
- R-07：按 playbook §6.2 接口实现（单项目模式 + --affected 模式），TS test 追加 -- --run，受限环境自导出 uv 缓存变量。
- R-03：GitHub Actions，6 job：setup(cache) / affected-js(lint+typecheck+build，test 按 JS 项目列表逐个跑) / python-lint(逐项目) / python-test(逐项目) / lock-check(uv lock --check + npm 校验) / alembic-check(5 个有迁移的服务)；不使用 test-ci（Nx Cloud atomized）。
- R-06：PR 模板（playbook §11.2）+ Conventional Commits 约定文档 + 归档双真源检查项。
- R-05：v2 内容为基底重写 architecture.md（修正 v1 过时事实、保留 ADR 清单），旧 4 份 git mv 至 docs/archive/2026-10/ 加注记；建 docs/README.md 索引与 docs/roadmap.md（活跃事项）。

## 5. 契约与兼容
无 HTTP/事件/DB 契约变化；CI 与门禁脚本为新增产物，不影响运行时。

## 6. 验证计划
- 自动化：R-01/R-04 后跑 npx nx test bff、npx nx test knowledge-service（验证 [^build] 链路）；R-07 后 gate 自测 common 与 @beauty/design；全仓 lint 抽查无新增错误。
- 门禁：见 §4 表。
- 人工：检查 CI YAML 逐 job 与本地命令等价；检查归档后无断链（grep 旧路径引用）。

## 7. 指标与验收
基线见 docs/refactoring/baseline.md；W0 出口按 playbook §10.3 W0 行执行并记录到 roadmap.md。

## 8. 风险与回滚
- CI 无法本地验证真实运行 → 缓解：job 命令与本地门禁矩阵逐条对照 + YAML 解析检查；遗留问题记入 roadmap。
- implicitDependencies 导致测试串行变慢 → 缓解：仅加边不加重型 dependsOn；实测 bff/knowledge 用例耗时对比。
- R-01 executor env 不支持 → 降级方案已定义（见 §3），不影响出口。
