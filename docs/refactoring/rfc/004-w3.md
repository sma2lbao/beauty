## 1. 背景与证据（2026-10-25 实测）

W2 收口后前端重复与体量问题已解决，**剩余技术债集中在 agent-orchestrator（AO）** 与工程 ratchet 缺失：

- **体量**：AO 源码 13516 行；services/runs.py 1100、services/mcp.py 792、services/conversations.py 682、services/skill_runner.py 666、services/mcp_oauth.py 660、services/skill_packages.py 624、services/mcp_stdio.py 607、graph/nodes.py 601、repositories.py 582、main.py 522、api/v1/runs.py 474、api/v1/conversations.py 463；
- **反向依赖**：graph/nodes.py:23-30 import services.\*，services/runs.py:28 import graph.delta，形成 graph ↔ services 双向依赖；
- **进程级单例**：graph/delta.py:32-40 用模块级 ContextVar + 全局 \_enabled/\_flush_chars/\_flush_seconds 承载增量落库，push 依赖外部先 configure，时序隐式；
- **API 层未瘦身**：api/ 共 1505 行，7 个文件直连 AsyncSession/仓储（27 处），10 处内嵌 SSE 帧拼接，app.state.\* 90 处，main.py 522 行承担全部组件装配；
- **common 依赖污染**：packages/common/pyproject.toml:18-19 的 pypdf / python-docx 被 10 个服务继承，实际只有 agent_orchestrator/services/attachments.py 使用 common.documents；common.metrics 混入 AO/gateway 域指标（gateway：completions.py:10、embeddings.py:6；AO：llm.py:16、runs.py:20、jobs_worker.py:15、usage.py:19）；
- **无覆盖率阈值**：11 份 coverage.xml 存在但全仓没有 --cov-fail-under；当前行覆盖（branch 覆盖）实测：common 86.4%(79.2)、database 92.9%(69.2)、events 97.9%(89.5)、AO 86.0%(67.4)、account 85.0%(29.9)、bff 84.8%(66.7)、connector 94.0%(66.7)、knowledge 93.1%(77.1)、llm-gateway 98.4%(81.0)、workspace 84.4%(57.1)；
- **零网络只是约定**：10 个项目的 addopts 无 pytest-socket，测试里真发请求不会被拦；
- **无黄金路径自动化**：scripts/ 只有 dev/seed/reset/gate/check-docs，端到端（会话→消息流→run→审批→交付物）无脚本。

## 3. 方案要点

### R-27（graph 去反向依赖 + 显式注入）

- 新增 core/ports.py，只放 Protocol：DeltaSink、UsagePort、ApprovalPort、ToolRegistryPort、LLMPort（services 侧实现，graph 只依赖协议）；
- graph/nodes.py 删除 from agent_orchestrator.services import approval/usage/llm/tools，改为从注入的 ports 取；
- graph/delta.py 去掉模块级 \_sink ContextVar 与全局可变配置，改为 DeltaProjector(sink, flush_chars, flush_seconds) 实例，由 builder 注入 state；
- services/runs.py 只保留 from agent_orchestrator.graph import ... 单向 import；
- 验收：graph 层 import services = 0；graph 层 ContextVar = 0（state 普通字段允许）；AO 386 用例不减、全绿。

### R-28（拆 services/runs.py）

目标形态（单文件 ≤300 行）：

```text
services/run_lifecycle.py   创建/取消/重试/状态机（状态迁移表 + 非法迁移拒绝）
services/run_events.py      run 事件写入与投影（build/append/list/next_seq）
services/run_stream.py      SSE 帧生成与断线续传（Last-Event-ID）
services/run_artifacts.py   交付物登记与预览引用
services/run_quota.py       配额校验与用量记账
services/runs.py            组合门面（对外函数签名保持，≤300 行）
```

- 对外函数（api 层调用的名字）保持不变，runs.py 保留 re-export 一层；
- SSE 事件序列契约不变：meta → delta\* → done（+ error），字段名与顺序沿用现状；
- 验收：runs.py ≤300；5 个新模块各自 ≤300；AO 386 用例不减；黄金 run（R-33）通过。

### R-29（api 瘦身 + AppContainer + services 按域分包）

- core/container.py 提供 AppContainer（settings/db/session_factory/repositories/services），main.py 只做装配（≤150 行）；
- api 层不再直接拿 AsyncSession/仓储：统一 deps.get_container(request) → 调 service 方法；SSE 帧拼接移入 services/run_stream.py；
- services 按域分包：services/mcp/（mcp_client/mcp_stdio/mcp_oauth/mcp_server/mcp）、services/conversations/、services/skills/（skill_packages/skill_runner），包内 **init**.py 仅导出稳定符号；
- 验收：app.state.\* ≤20；api 层 AsyncSession 直连 = 0；api/ 最大文件 ≤300；main.py ≤150；AO 386 用例 + 黄金 run 通过；HTTP 路径与响应体不变（OpenAPI 快照 diff 为空）。

### R-30（common 瘦身，缩水版）

- common/documents.py 迁到 agent_orchestrator/services/documents.py（AO 自己维护解析），packages/common/tests/test_documents.py 随之迁到 AO tests；
- 从 packages/common/pyproject.toml 移除 pypdf / python-docx，AO 的 pyproject 加上；uv.lock 由 npx nx run <项目>:sync 更新；
- common.metrics 的 AO/gateway 专属指标（observe*llm*_、observe*run*_、observe_job_failure）加 docstring 归属标注与 TODO(W4) 拆到服务本地，本轮不搬（避免与 R-28 争用 runs.py）；
- 验收：common 内 pypdf / python-docx 引用 = 0；bff / llm-gateway 的 uv 依赖树不再含这两个包；common 96 用例、AO 386 用例全绿。

### R-31a / R-31b（覆盖率 ratchet）

- Python：每个项目 [tool.pytest.ini_options] addopts 追加 --cov-fail-under=<实测行覆盖向下取整>（common 86、database 92、events 97、AO 85、account 85、bff 84、connector 94、knowledge 93、llm-gateway 98、workspace 84）；实测值入 baseline；
- TS：vitest coverage.provider=v8，thresholds 取实测值向下取整，覆盖 web / design / console-ui / desktop / site；
- 口径约定：ratchet 只允许上调，下调必须在 RFC 或复盘里写明理由；
- 验收：npx nx run-many -t test -- --run 与 10 项目 pytest 全绿；故意删一个测试时该包失败（探针验证）。

### R-32（零网络硬门禁）

- 每个 Python 项目 dev 依赖加 pytest-socket，addopts 追加 --disable-socket --allow-unix-socket；
- 需要真实网络的用例（Postgres testcontainers、外部 HTTP 桩）显式 @pytest.mark.enable_socket 或 conftest 里放行；
- 验收：724 用例全绿；新增临时探针用例（httpx.get(example.com)）必须被拦并报 SocketBlockedError；CI python-test 不变。

### R-33（黄金 run）

- scripts/golden-run/（Python，uv run）以 ASGI transport 在进程内驱动 AO：创建会话 → 发消息（SSE 收 meta/delta/done）→ 复杂任务建 run → 审批通过 → 产出交付物 → 断言事件序列与 DB 状态；
- 依赖：临时 sqlite 文件库 + 假 LLM（stub gateway，固定回复 + 一个工具调用）；零网络（配合 R-32 的 disable-socket 也必须能跑）；
- 输出：阶段表（阶段 / 断言 / 耗时 / PASS|FAIL）+ 退出码；--keep 保留临时库便于排查；
- 验收：bash scripts/golden-run.sh EXIT 0；连跑两次结果一致；用法写入 docs/local-dev.md。

## 10. 偏差登记（本 RFC 相对 playbook）

1. playbook §10.3 W3 指标写「最大 Python 文件 ≤500」：本 RFC 拆两步，W3 ≤700、W4 收到 ≤500。理由：>700 的 6 个文件（mcp 792 / conversations 682 / skill_runner 666 / mcp_oauth 660 / skill_packages 624 / mcp_stdio 607）分属 R-29 分域范围，与 R-27/R-28 同波全拆会让 AO 一次性重写 5000+ 行，回滚面过大。收口时更新 playbook §10.3。
2. R-30 从「common 瘦身全量」缩为「documents 移出 + 依赖隔离 + metrics 标注」：metrics 域指标真实拆分与 R-28 争用 runs.py，顺延 W4。
3. R-32 与 R-33 顺序对调（第 4 节）：黄金 run 先立，零网络门禁最后开，避免 socket 拦截过早挡住 e2e 试验。
