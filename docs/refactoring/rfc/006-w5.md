## 4. 方案要点

### R-41 体量拆分的形态约定

- **包化**（模块有多个类/多组职责）：原 `x.py` → `x/` 包（`__init__.py` 门面重导出全部原名字，含被测试 import 的私有名）。
- **兄弟模块化**（模块有单一对外门面）：原 `x.py` 保留为门面（重导出 + 入口），实现迁到 `x_<职责>.py`。
- 拆分按"职责/生命周期阶段"切，不按行数硬切；保留原 docstring/注释（内容不删，位置可迁）。
- **不动**函数签名、异常类型、错误信封、日志文本、SQL、事件语义、HTTP 契约。

### R-43 装配收敛的形态

- 能完整套用 `create_service_app` + `build_lifespan` + `create_health_router` 的服务：account-service、workspace-service、agent-orchestrator（自管资源用 `startup=` / `shutdown=` 钩子，顺序不变）。
- 无数据库的服务（llm-gateway）只复用 `create_service_app` / `create_health_router`，保留自建 lifespan。
- bff 保留其特殊就绪语义（上游/配置判定），通过 `create_health_router(ready_check=...)` 表达；若 kit 缺能力，**在 kit 内增量补齐并补 common 测试**，不改服务侧语义。
- 健康探针路径与状态码/响应体不变（`/healthz` 200，`/readyz` 200/503）。

### R-44 死配置

删除键后在同文件与全仓 `grep` 确认无残留；服务侧 `.env` 若有对应键保持不动（pydantic-settings 忽略多余键）。

### R-45 ratchet

`scripts/check-python-size.sh`：扫描 `services/` 与 `packages/` 的 `.py`（排除 `migrations/`），断言 ≤500 行；例外白名单以"路径:原因"形式内联（当前仅 `services/tool-service/helpers/fs_helper.py`）；接入 `refactor-gate.sh` 的全局检查段与 `check-workspace.sh` 同级。

## 5. 契约与兼容

- **import 路径不变**：所有被拆模块的公开路径继续可用；已知需要显式保住的私有名：`agent_orchestrator.graph.nodes._record`（`tests/test_tool_audit.py:12`）、`agent_orchestrator.services.run_execution._invoke_plan`（`services/subagents.py`）。
- **测试资产不变**：测试文件可拆，用例数与断言强度不减（基线见 §7）。
- **公开 API 不变**：本波不新增/不删除服务对外路由与响应字段。
- **例外 D1**：`services/tool-service/helpers/fs_helper.py`（1058 行）经 `python3 -c <整份源码>` 注入沙箱（`tool_service/services/helpers.py` 的 `helper_source()`/`helper_argv()`），物理上是单文件纯 stdlib 脚本，拆分会改变执行契约。参照 W3 D8（`golden_run.py` 808 行行为脚本例外）登记为体量例外，本波仅记录、不拆。

## 8. 风险与回滚

| 风险                                         | 影响                    | 缓解                                                                      |
| -------------------------------------------- | ----------------------- | ------------------------------------------------------------------------- |
| 拆包改坏 import（尤其私有名）                | 大面积 collection error | 门面重导出 + 全量 pytest；逐片验证后才提交                                |
| AO 三源码切片 + 测试切片并发，互相看到半成品 | 误判失败                | 约定：失败先判断归属，不替他人改文件；每片自检相关测试，Lead 收口时跑全量 |
| 装配收敛改变中间件/探针顺序                  | 认证/观测/健康语义变化  | 严格按 service_kit 既有顺序，逐服务对比原 main.py 并跑全量测试            |
| 拆包导致覆盖率统计口径变化（同名包）         | `--cov-fail-under` 波动 | 保持包路径与被测模块一致；收口时逐项目核对覆盖率                          |
| 拆分引入循环 import                          | 运行期 ImportError      | 保留原模块门面、必要时延迟 import（不改行为）                             |

回滚策略：每切片独立提交，出问题按切片 `git revert`（提交粒度见 verification/006-w5.md）。例外 D1 不引入新机制，无需回滚路径。
