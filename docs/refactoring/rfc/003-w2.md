## 1. 背景

W1 已把前端基座（env / queryKey / HTTP client / SSE / presentation / 路由拆包 / 文档门禁）打通，重复实现归零，但**单文件体量**与**跨端重复**仍是主要技术债：

- `apps/web/src/pages/chat.tsx` 1320 行、单组件承载 8 个 useQuery / 6 个 useEffect，同时耦合 conversations 与 runs 两域；
- `mcp.tsx` 936、`sidebar.tsx` 666、`workspace.tsx` 598、`settings.tsx` 461 行，均为「页面 + 表单 + 数据获取 + 业务规则」混装；
- `apps/web` 与 `apps/desktop` renderer 是纯拷贝分叉（约 1300 行会话 UI + 311 行原语），`apps/site` 与 `apps/web` 存在字节级重复工具与两份已分叉的 brand logo；
- Python 侧七个服务的 `main.py`（46–139 行）、`health.py`（7 份、5 种 md5）、conftest（7 份）同构但各自复制，Fernet 实现 4 份、SlidingWindowLimiter 2 份、X-Internal-Secret 校验散落 3 处；
- 配置与测试基建未收敛：tsconfig 未被统一 extends、vitest 配置 4 份、`apps/site` 零测试、`components/console` 21 个源文件仅 5 个测试。

W2 的目标是**在不改变任何外部行为**的前提下，把「大文件」拆成按域组织的模块，把「复制粘贴」收敛成单一实现，并在 Python 侧试点 service-kit。

## 3. 方案要点

### R-17（chat.tsx）

目标目录：

```text
apps/web/src/features/chat/
  use-chat-queries.ts    会话/消息列表与变更
  use-chat-stream.ts     SSE 订阅、投影、重连与追加指令
  use-chat-actions.ts    发送、审批、停止等命令
  message-list.tsx       消息渲染（含工具调用卡片、markdown）
  composer.tsx           输入区与发送方式（自动/对话/任务）
  approval-block.tsx     审批/确认内联交互
  chat-page.tsx          组合外壳（≤120 行）
```

- `pages/chat.tsx` 退化为 re-export（≤20 行）；
- 测试按域拆为 3–4 个文件，保留现有 311 用例中的 chat 部分**全部断言**，不允许减少覆盖点；
- 等价性证据：拆分前后各录一份「发消息 → meta/delta/done → run 创建/并入 → 审批按钮」的黄金路径人工核对表。

### R-18（四页）

同法：页面文件只保留「路由参数 → 组合 → 布局」，数据获取/hooks 落 `features/<domain>/`。单文件目标 ≤400 行（sidebar ≤350）。**不得改动** `ui.tsx`、`dialog.tsx`（R-26 所有）与 `chat.tsx`。

### R-20（site 去重）

- `apps/site` 的 `utils.ts` 与 web 重复的类名工具删除，改引 `@beauty/design` 导出；
- brand 标识统一到 `@beauty/design`（R-26 负责归位后由本项接入），site 不再保留副本；
- About 页壳与 web 的 `pages/about.tsx` 收敛为同一份内容组件（site 用 Next 的 `export const metadata` 包裹）。

### R-21（配置收敛）

- `tsconfig.base.json` 置 `strict`/`module`/`moduleResolution`/`target`/`customConditions`，各项目 `extends` 它，删除重复字段；
- vitest：根 `vitest.config.mts` 提供 shared options，`apps/*/vitest.config.mts` 只保留差异（environment/alias）；
- `apps/site` 至少补 3 个测试（layout metadata、sitemap/robots 输出、landing 关键 CTA）；
- `components/console` 为 4 个无测试的关键组件补测试（`run-detail`、`workspace-actions`、`execution-panel`、`diff-view`）。

### R-26（design 单一来源）

- `packages/design` 提供 `BrandMark/BrandTile/BrandLockup` 与 `Dialog`/`Button` 的完整能力；
- `apps/web/src/components/console/ui.tsx` 缩减为「设计系统组件的薄适配层」，禁止自建 Dialog/Button；
- 主题令牌只保留一份定义（`--bd-*` → web 的 `--ha-*` 通过映射引用，不再并行定义两套色值）；
- brand logo 单一来源移入 `packages/design`，web 与 site 都从该处引用。

### R-25 / R-22 / R-23 / R-24（Python）

- R-25：`common/security/` 提供 `secret_box`（Fernet 封装，密钥派生规则与现实现**逐字节兼容**）、`SlidingWindowLimiter`、`require_internal_secret` 依赖；各服务改引用，删除本地实现；
- R-22：在 `common/service_kit/` 提供 `create_service_app(name, routers, lifespan_hooks)`、`health_router(service_name)`、`auth_dependencies(settings)`、`BaseAppSettings.auth_*` 字段与校验、限流中间件；先迁 connector 与 knowledge，其余服务 W3 跟进；`common` 新增 `fastapi`、`uvicorn` 依赖（已在其 middleware 中隐式使用）；
- R-23：`common/testing.py` 提供 `service_test_client` / `make_settings`，默认钉死零网络开关；7 份 conftest 改为薄封装；
- R-24：alembic env 模板共享（`database.alembic_env`），5 个服务 env.py 只传 URL 与 target metadata；新增迁移 smoke：`alembic heads` 唯一且 `create_all` 后 `alembic check` 无差异。
