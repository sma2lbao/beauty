## 3. 做对了什么

1. **先立 ratchet 再拆分**：`check-python-size.sh` 先落地并在拆分前实测「24 违规 / EXIT 1」，拆完归零才有证明力；gate 与 CI 接线同样做在前面，避免「拆完忘了加门禁」。
2. **门面重导出 + 私有名清单**：拆包前先 grep 全部引用方（含测试直接 import 的 `graph.nodes._record`、`completions._get`、`run_execution._invoke_plan`），把「重导出清单」写进 RFC §5 契约，7 片按契约交付，1885 例零回退。
3. **写域文件级互斥 + 7 片并行**：AO 占 5 片且同在 `services/` 下，但每片只碰自己的文件清单（新增各自兄弟模块），提交时按片 `git add -- <清单>`，13 个提交之间无交织、无半成品。
4. **逐片验证后立即提交**：每片先跑目标服务全量 pytest + ruff + 行数再提交；全量 11 项目矩阵留到最后一次串行跑，避免并发抢 `reports/` 与中间态失真。
5. **既有红与本次改动分离取证**：golden-run 1/9、ruff format 漂移、llm-gateway tests 的 3 个 lint 错，全部在基线提交 4717b3f 的干净主仓库复跑确认后才登记 D2/D3/D4——修与不修都有据。

## 4. 教训

1. **monkeypatch 目标是拆分的隐形约束**：本轮至少 7 处 patch 目标因拆分换了模块归属（`container_module.build_run_graph`、`subagents._wait_child`、`execution.find_descriptor`、`_import_sdk` 等）。规则：拆任何模块前先 `grep -rn "monkeypatch.setattr\|patch("` 出目标清单，再决定拆分缝与「哪个名字必须留在门面」。
2. **门面重导出必须含私有名**：测试直接 import 私有名是既有事实，只导 `__all__` 会静默丢契约（还不会有任何报错，直到测试变红）。规则：门面以「HEAD 模块命名空间全量」为基线，用 AST 比对补齐。
3. **单文件体量与总行数是两个指标**：拆分让总行数 +13.5%（门面/`__init__`/文件头开销），只盯总量会误判「越拆越大」。规则：ratchet 阈值只按单文件设（500），总量做趋势观察，不进阈值。
4. **动手前先在基线复跑门禁**：golden-run 与 format 漂移都是「复跑 4717b3f」之后才敢定性为既有。规则：每波开工第一步把要引用的门禁在基线提交跑一遍并贴输出，作为对照证据。
5. **并发 agent 共享 venv/reports/**：中间态一律 `-o addopts=""` 跳过覆盖率，只有收口时由 Lead 串行跑全量收集；否则 `coverage/services/*` 与 `reports/*` 互相覆盖、cov-fail 误报。
6. **`git ls-files --cached` 会列出已删未提交文件**：py-size 在「删除 + 新增」中间态直接 EXIT 2 且无输出，属脚本健壮性坑（7d35939 修）。规则：门禁脚本遍历索引必须 `[ -f ]` 守卫并给出可读输出。
7. **大测试文件按行为域切，不按行数均分**：5 个测试文件都按「http/toolkit/audit」「spawn/tool/projection」这类主体拆，共用 fixture 抽到 `tests/fixtures/`、`tests/support/`；按行数硬切只会制造重复 setup。
