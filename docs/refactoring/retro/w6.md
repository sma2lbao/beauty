## 3. 做对了什么

1. **搬家与拆分分离**：R-46 只做"位置与 import 的等价搬迁"（27 个组件 + 6 个测试，脚本全量替换 30 个文件的 import），随后每个拆分项才从干净起点切；console 只剩外壳与原语，R-53 的规则目标才可精确表述（"原语不得依赖 features"）。
2. **规则先探针后上线**：R-53 三条规则先用 `npx eslint --stdin --stdin-filename` 造 7 个样本（命中 4 / 豁免 3）确认生效，再跑全量 lint；避免"规则写了但没命中"或误伤外壳与测试。
3. **5 片并行 + 写域互斥**：task-1..task-5 各占一个 `features/<domain>`，无一处交叉；每个 teammate 交付前自跑 typecheck / lint / test 并贴数，Lead 只做收口复跑与提交。
4. **"测试零改动"当硬约束**：所有 `*.test.*` 断言零增删，改动文件逐条对账为 import / `vi.mock` / 头注释；行为等价从口号变成可核查证据。
5. **去重按正版归并并登记偏差**：formatBytes 三份收敛到 `lib/presentation/format.ts`，顺带把 `!isFinite || <= 0` 兜底补齐；file-tree 的可见文案随之从 `2.0K` 变成 `2.0 KB`，登记 D1 而不是悄悄改。

## 4. 教训

1. **立项前必须对远端做编号预检**（本轮最大代价）：本地按 W5 / RFC-006 立项并已完整收口 11 个提交，准备发 PR 时才发现 `origin/main` 已合并同编号的 W5 / RFC-006（services 装配波次）。代价 = 重新编号（W6 / RFC-007 / R-46..R-54）+ 8 个代码提交重放 + 4 个文档重写。规则：RFC 起草第一步 `git fetch`，并核对三处——`docs/refactoring/rfc/` 远端文件名、`roadmap.md` 波次序号与 R 号段、`origin/main` 最近提交的主题。
2. **rebase/cherry-pick 前先做 `git merge-tree` 预演**：本轮预演一次就确认冲突面只有 4 个文档（两个 add/add），148 个 `apps/web` 文件可自动合并，才敢用 cherry-pick 重放；否则会在中途撞车后再回滚。
3. **追加波次文档段落不能打断既有表格**：W5 收口时 baseline.md 被"末尾追加"切成 4 行表头 + 11 行残表、中间夹着收口表；本次重建为单一完整表。规则：追加一律整段追加，改完 `grep -c '^| 维度'` 校验表头数。
4. **搬家类 R 项必须排第一且独占测试文件**：R-46 一次改 6 个测试文件的 import / `vi.mock`，若与拆分片并行必然互相踩；本轮靠顺序（先搬完再并行）规避。
5. **warn 规则要有人负责升级**：R-53 三条规则全 warn 且当前 0 命中，若无跟踪项就会永远停在 warn；已写入 roadmap 遗留项（观察 1–2 个波次后评估升 error）。
6. **文档互相引用要跟着编号走**：AGENTS.md 的结构分工句、roadmap 遗留项、baseline 表头都引用波次号与 verification 路径；改编号后需全仓 grep 旧编号兜底（本轮 `006-w5` / `W5` 各查一遍）。
7. **提交信息也是编号的一部分**：8 个代码提交的 subject 里带着旧 R 编号（`（R-41）` 等），PR 里会与 roadmap 的 R-46 表对不上。补做一次 `git filter-branch --msg-filter` 重写信息（树不变），哈希因此二次变化，文档里的提交号需再回填一轮。规则：改编号时把「提交信息」列入清单，且改写前后用 `git diff <旧tip> <新tip>` 证明树未变。
