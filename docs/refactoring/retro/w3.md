## 做对了什么

1. **先立黄金 run 再动内核**：R-33 在批次 A 最先落地，之后每次拆 graph/api 都能用一条命令回归端到端行为，比逐层读 diff 可靠。
2. **契约快照先行**：R-29 第一步 dump `app.openapi()`（158940B），22 个文件改动后快照零差异，是这次最大改动仍敢合并的关键。
3. **阈值按实测口径校准**：R-31a 初版按 line% 定，AO 开 branch 后立刻暴露出「比的是 combined」，当天重设；覆盖率门槛没变成假指标。
4. **零网络门禁逼出两个真缺陷**：连接泄漏（SAWarning）与上报 fail-open（ExceptionGroup 逃出 finally）都不是重构引入，而是原有代码在禁网后显形——门禁提供了发现通道。
5. **拆分用脚本按顶层单元切分**（mcp.py / conversations.py），再用 `__all__` + 自别名 re-export 保持调用方零改动，避免了 5000 行手工重写。

## 教训

1. **「nx 下失败、直跑通过」必须按环境差异查，不能记 flake**：两个 quota 用例被两轮误判为并发干扰，实际是 Nx 注入 .env + 装配真实 account URL + 上报只捕 httpx.HTTPError。下次先 diff `nx test` 与 `uv run pytest` 的 env。
2. **禁网门禁会改变异常类型**：socket 被拦时传输层抛的是任务组包装的 ExceptionGroup，任何「只捕 HTTPError」的 fail-open 都会失效；观测类调用一律 `except Exception`。
3. **提交前 typecheck 要覆盖所有受影响包**：R-31b 只验了 web，console-ui/design/desktop 的 `vitest.config.mts` 被 spec tsconfig include 后立刻报 TS5097/TS6059。
4. **heredoc 写代码会二次转义**：documents.py 曾出现真实 NUL 与裸换行导致整包不可 import；写代码一律 edit/write + `py_compile` 自检。
5. **测试断言要跟着懒加载改**：R-10 之后 `/` 是 React.lazy 路由，覆盖率插桩 + 并行 worker 下 findBy 默认 1s 偶发不够——门禁假红一次，已把等待上限放宽到 5s（断言内容未放宽）。
6. **lint 也要真跑**：`npx nx run-many -t lint | grep` 的退出码来自 grep 不是 lint，一次 E501 因此混过提交（已 amend 修）。
