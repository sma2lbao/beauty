## 做错了什么（教训）

1. 「CI 已绿」在 W0/W1 是不成立的结论：.github/workflows/ci.yml 有 24 处模板表达式被写坏成 ${D} ... }}（heredoc 生成事故），python-lint/python-test/alembic-check 从未真正执行。教训：门禁类结论必须附 run 链接 + job 结论表；workflow 文件提交前必须 js-yaml 解析 + 关键表达式与 }} 配对校验。
2. 本地 lint 通过 ≠ CI lint 通过：bff/AO 的 4+2 处 I001 import 排序本地绿、CI 红（venv 里 first-party 包集合不同导致 isort 分组不同）。教训：lint 规则类修复推送后必须看 CI 结论再宣称完成。
3. 依赖 engines 下限没跟传递依赖对齐：Node 20.19 下 vitest 直接 TypeError: webidl.util.markAsUncloneable is not a function（jsdom 30.1.2 要求 ^22.22.2 || ^24.15.0 || >=26、undici 8.11 要求 >=22.19）。教训：升级依赖或换 runner 前先查 npm ls engines；Node 版本变更同步 .nvmrc / package.json engines / README / AGENTS.md / docs/local-dev.md 五处。
4. alembic check 不能用 sqlite 代替：AO/account 迁移含 PG 专有 DDL，sqlite 直接 near "ALTER": syntax error；docker service 的 --health-cmd "pg_isready -U beauty" 参数必须加引号，否则 docker 把 -U 当自己的 flag（unknown shorthand flag: 'U' in -U）。教训：迁移检查固定 Postgres 容器 + health-cmd 带引号。
5. 共享工作树严禁 git stash / reset --hard / checkout -- <他人文件>：audit-python 做回滚演练时用 git checkout HEAD -- <自己的文件> 让 R-25 改动整批消失。教训：演练一律 git diff > p && git apply -R --check p，禁止触碰工作树。
6. 两个队员各空转 75 分钟零落盘：w0-docs（R-26）、w0-ci（R-21）长时间只勘察不写代码。教训：派工必须带时间盒（首个落盘 ≤20 分钟）+ 分段交付，lead 每 20 分钟查 git status，无改动即拆段或改派。
7. 波次预算低估既有债：W2 计划 10 项，实际 6 个配套修复（CI 表达式、Node 下限、alembic Postgres、模型漂移、isort、desktop 进程组）占掉近半工时。教训：首次真正跑通门禁的波次必须预留 30% 预算给「门禁暴露的既有债」。
