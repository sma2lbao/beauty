## 5. 偏差与处置

1. **R-17/R-18 体积远超 400 行**：拆分只能在单提交内完成（跨文件引用），已按 §10.4 记录例外；等价性用「生产代码拆完、测试未动时原 27 例全绿」证明。
2. **R-19 触碰共享构建面**：apps/web/src/index.css（Tailwind @source）、两个 app 的 package.json 与 tsconfig references；后续 R-26 改同一文件时保持 @source 行未被覆盖。
3. **R-20 的 RSC 限制**：Server Component 里 import 包根会把整套组件库拉进 RSC 依赖图并报 useState 错误，改为子入口 "./brand" + 'use client'；next build 会改写 apps/site/next-env.d.ts，属生成物，每次 build 后 git checkout 回退。
4. **R-24 偏离 RFC 落点**：canonical 模板放 common.alembic_kit 而非 database（database 是纯 ORM 基座，5 个迁移服务本已依赖 common）。
5. **R-26 已知视觉差异**：Button md 34px/14px、lg 40px/16px、圆角 8、danger 实心；Dialog 宽 32rem、标题 16、描述 14、footer 有上边框 —— 接受（统一到 design 语义，W4 发布前人工核对截图）。
6. **R-21 只做文档化收敛**：vitest 子配置的物理抽取留待后续波次，本轮仅加共享约定注释块，收集范围零变化。
7. **CI 自 W0 起一直是红的**：ci.yml 有 24 处模板表达式被写坏成 `${D}`，W0~W1 期间「CI 已绿」的结论不成立；本轮修复后首次真正全绿（见 retro/w2.md 教训 1）。
