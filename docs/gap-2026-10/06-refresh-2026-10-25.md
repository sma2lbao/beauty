## 0. 一页结论

1. **「入场券」已经拿到。** 旧册列的 P0 七项基本落地（commit `4b17cf3`），叠加沙箱 P1–P3、stdio MCP、公开 MCP Server、OTel/Sentry/metrics、CI/Docker、技能包、黄金 run、`token.delta` 流式，beauty-moon 已过了「单 run 闭环」门槛。
2. **差距从「有没有」变成「harness 机制代差」。** 2026 年竞争单位是 agent harness：同一模型换 8 个 harness，25 任务成功率 68% → 88%（marmelab 审计）。主流基线已上移一档：durable execution、子代理、上下文压缩、hooks、eval、MCP 无状态规范。beauty-moon 真正缺的是**机制五件套：上下文压缩、子代理委派、hooks、checkpoint 回退/续跑产品面、eval 闭环**。
3. **但有 6 处「正确性 / 商业化断点」必须先于机制补齐**（P0）：成本归因不可见且 usage 会丢账、run 生命周期空洞（`planning/running` 从不赋值、无 cancel、审批可无限悬挂）、多实例正确性（job 无心跳、outbox claim 无锁、reaper 无锁）、对话直答路径无配额闸、MCP server 注册无 SSRF 校验、BYOK 存而不用。**其中 P0-2 已于 2026-10-25 晚、P0-6 已于 2026-10-26 落地**，剩余四件见 §3.1。
4. **旧册的对比结论有 7 类已过时、1 处写错。** 过时：P0 六项、Dockerfile、CI、OTel/metrics、MCP stdio、沙箱、技能包、SKIP LOCKED、工具轮次（3→5）、邮件/日历连接器。写错：MCP 不该补 sampling/roots/logging（2026-07-28 已弃用），要补的是 elicitation、tasks 扩展与无状态语义。
5. **行业整体工程成熟度仍低**：97 个够大的 harness 中 60% 无 test 也无 eval，145 个大型 OSS 里只有 4 个声明 subagent、全部只有 14 个 hooks。**eval 与 hooks 是当前性价比最高的差异化**，不是「可延后项」。
6. **排期建议**：先做 P0 六件（约 2–3 周）→ 再做 P1 机制五件套（约 4–6 周）→ 最后 P2 生态（SDK/A2A/对象存储）。Temporal、外部记忆服务、插件市场、computer use 继续暂缓，恢复条件见 §3.4。

## 3. 需要补齐的能力清单（按优先级）

> 分组口径：**P0 = 正确性/商业化断点**（不做会丢钱、丢数据、丢部署正确性）；**P1 = harness 机制代差**（主流正在变成入场券）；**P2 = 生态/产品化**（有明确触发条件再做）。每条给出现状证据、主流做法、规模。

### 3.1 P0：正确性与商业化断点（建议 2–3 周）

**P0-1 成本归因与计费可见性（M）**

- 现状：usage 只有 token 计数（`run_id/model/prompt_tokens/completion_tokens`，`services/usage.py:108-113`），无金额/价格表/阶段维度；上报失败静默丢账（`llm.py:199-204/272-276`）；前端无成本视图（usage 页只有 token）。
- 主流：LiteLLM 成本映射、Langfuse generation cost、Helicone 按请求成本；SaaS 平台「每个 run 多少钱」是标配（[S20]）。
- 影响：无法定价、无法给租户看账单、无法定位哪个 run 烧钱；丢账会直接低估用量，配额形同虚设。
- 动作：价格表（按 provider/model）→ usage 增 `cost_usd`/阶段/agent 维度 → 失败重试+本地缓冲 → 前端用量页展示成本与预算水位。

**P0-2 run 生命周期收尾：状态机 / 取消 / 超时（M）——✅ 已于 2026-10-25 落地**

- 审计时现状：`planning/running` 从不赋值；无 run cancel；审批与确认中断无超时（可无限悬挂）；`blocked` 才能 resume（`run_lifecycle.py:33`）；前端 running 过滤恒空。
- 主流：Claude Code 可 ESC 取消、后台任务可管理；LangGraph 状态由事件推导（[S3][S9]）。
- 影响：用户点「停止」没有 API；前端状态失真；企业评审无法回答「这个 run 跑了多久/卡在哪」。
- 动作：事件投影出真实状态（或补赋值）→ `POST /runs/{id}/cancel`（协作式取消 + 终态事件）→ 审批/确认超时策略（默认拒绝/自动挂起）→ 前端状态与过滤修正。
- **落地记录**：`planning`/`running` 赋值（`run_execution.py`、`run_execution_approvals.py`）；`run_cancel.py` + `POST /runs/{id}/cancel`（终态 409、撤 queued job、`run.cancelled.v1`）；`interrupts.py` sweeper（复用 reject/confirm job，事件 `run.interrupt.timeout.v1`，确认超时补写 `run.confirmation.received.v1`）；前端 `cancelled` 状态/看板列/取消按钮/通知。**残余**：状态变更不落独立事件、取消与完成同刻竞态、sweeper 依赖 jobs worker——并入 P0-3 与 `07-run-step-model.md` §S1。

**P0-3 多实例正确性：job 心跳 / outbox claim / reaper 锁 / 限流（M）**

- 现状：job claim 设 60s lease 但**不续租**（`jobs_worker.py:94/116/129`），长 run 可能被第二实例重复领取；outbox dispatcher claim 无 SKIP LOCKED（`events/outbox.py:119-133`）；沙箱 reaper 无跨实例锁（`workspace/services/sandbox.py:355-387`）；限流进程内（`bff/main.py:67-94`），OAuth 动态注册限流同样进程内。
- 主流：DB 行锁/SKIP LOCKED + 心跳续租；Redis 分布式锁/限流；Temporal/Inngest 的 lease 语义。
- 影响：一旦 docker compose 多副本或滚动升级，出现重复执行、重复回收沙箱、重复发事件。
- 动作：lease 续租 + 心跳丢失即释放；outbox claim 改 SKIP LOCKED + 处理中标记；reaper 加 DB 锁；限流切 Redis（R-P1-8）。

**P0-4 对话直答路径的配额与预算闸（S–M）**

- 现状：chat 直答不建 run，也不检查配额（`chat.py`/`conversation_messages.py` 无 quota 引用）；run 准入 fail-open（account 不可用时放行）；前端不显示余额。
- 主流：每条推理请求都经租户配额/预算准入；超限 402/429 并提示。
- 影响：对话是最高频路径，却完全绕过计量闸——成本失控与「无限免费」风险都在这里。
- 动作：chat 调用前查配额/预算（复用 `run_quota`）→ fail-open 改为可配置（默认 fail-closed 或仅告警）→ 前端展示剩余额度与超限提示。

**P0-5 MCP server 注册 SSRF 与「工具面静默降级」可观测（S–M）**

- 现状：HTTP MCP server URL 注册无 SSRF 校验（可填私网/回环）；MCP 工具加载异常被吞掉降级为空工具面（`graph/nodes.py:98-133`），计划审批闸据此判断「无危险工具」，可能自动放行；执行期 DANGER 仍进确认闸（`nodes.py:274-296`），所以风险主要是「批准计划时看不到将要用的工具」与控制流不一致，而非未确认即执行。
- 主流：server 注册做 URL allowlist/私网拒绝/出网代理；工具发现失败显式报错或告警。
- 动作：注册时 URL 校验（拒私网/回环/元数据地址）；加载失败落事件 + 告警 + 计划里标注「工具面不完整」；确认闸口径与执行期一致。

**P0-6 BYOK：接入或明确下线（M）——✅ 已于 2026-10-26 落地（选择「接入」）**

- 现状（审计时）：account 加密存储租户 key（`insights.py:126-152`），llm-gateway 完全不用（`completions.py:116-120` 只读 `settings.api_key`），默认还是 dev 占位密钥；文档却写「按租户选 key」。
- 主流：网关按租户/请求注入 provider key，并做 KMS/轮换/脱敏。
- 影响：用户以为「切了自己的 key」，实际仍烧平台额度——承诺与实现不一致，比没有功能更伤信任。
- 动作：二选一。接入：llm-gateway 按 `X-Tenant-Id` 取 key（缓存+失败回退平台 key+审计）；下线：前端/文档标注「即将支持」，移除过度声明。
- 落地（2026-10-26，选「接入」）：account 引入信封 v2 + `BYOKKms`（local / Vault Transit，`account/core/byok_kms.py`）与内部 `GET /v1/byok/{provider}/secret`（`X-Internal-Secret` + `X-Tenant-Id`，`Cache-Control: no-store`）、`POST /v1/byok/rotate`；llm-gateway `services/byok.py` 按租户解析（TTL 300s / 负缓存 30s / LRU 1024 / 单飞锁），任何失败回退平台 key，观测 `llm_byok_lookups_total{status}`；completion/stream/embeddings 三路接入，orchestrator 与 knowledge 出站钩子注入租户头与内部密钥。契约见 [design/byok.md](../design/byok.md)。
- 残留：无独立审计表；用量未区分 byok/platform（P0-1）。容器编排已补 `LLM_GATEWAY__ACCOUNT_BASE_URL`（2026-10-26）。

### 3.2 P1：harness 机制代差（建议 4–6 周）

**P1-1 上下文压缩与工具输出 offload（M–L）**

- 现状：`history.py:19-30` 最近 20 条 × 单条 2000 字硬截断；无摘要、无压缩事件、无工具输出落盘。
- 主流：Claude Code `/rewind` 的 Summarize from here、自动压缩；Deep Agents 的工具输出 offload 到文件系统（[S3][S10]）；AGENTS.md/CLAUDE.md 约定文件。

- 动作：token 水位估算 → 触发摘要（保留最近 N 条 + 摘要 + 工具输出引用）→ 事件投影 → 前端水位与「已压缩」标记。
- 已落地（2026-10-25）：见 [memory.md](../design/memory.md)（m00103 实现）；压缩摘要 + `run.compacted.v1` 事件已落地（后端），前端上下文水位仍缺。

**P1-2 子代理委派（L）**

- 现状：`parent_run_id` 只用于 retry，无子 run 委派/子代理工具。
- 主流：Claude Code subagents（独立上下文/工具/权限/更便宜模型）、Cline `spawn_agent`、Qwen Code SubAgents + Agent Teams、Deep Agents sub-agents、OpenHands Agent Canvas 跨 agent 编排（[S3][S4][S18][S10][S12]）。

**P1-3 harness hooks（M）**

- 现状：只有 httpx `event_hooks`，无应用级生命周期钩子。
- 主流：Claude Code 20+ 事件/五类处理器、Cline hooks/plugins（[S3][S4]）；行业全部 145 个大型 OSS 只有 14 个 hooks，做扎实即差异化。

- 动作：hooks 表（租户级）→ 图节点调用点（工具执行前后、run 开始/结束、压缩前）→ 输出回喂/阻断 → 前端管理页。

**P1-4 checkpoint 回退与续跑产品面（L）**

- 现状：生产 PG checkpointer 已接（`container.py:429-465`），dev InMemory；但无快照列表/回退/fork API，也没有 UI；恢复路径只有 `blocked` 的 resume。

### 4.3 MCP 规范变化（破坏性，必须单列）

- **2026-07-28**：移除协议级会话、`initialize` 握手、GET+SSE；改为完全无状态请求 + `server/discover` + `subscriptions/listen`；`tasks` 移出核心成为官方扩展（[S5]）。
- **弃用**：`sampling`、`roots`、`logging`（[S6]）——旧册建议补 sampling 是错的。
- **仍有效**：`elicitation`（服务端请求用户补充信息）、tools/resources/prompts 基本模型。
- beauty-moon 现状：公开 server 与 client 均按 2025-03-26 语义；需要做「新旧双栈兼容 → 灰度 → 切默认」的协议对齐。

### 4.4 协议分层（2026-10）

MCP（agent ↔ 工具）· A2A（agent ↔ agent）· AG-UI（agent ↔ 前端）· ACP（编辑器 ↔ agent）。beauty-moon 已有「事件流 → SSE → 前端」的同构基础，AG-UI 是性价比最高的下一协议（interrupts/state 与现有审批/run 状态几乎一一对应）。
